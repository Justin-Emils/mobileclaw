## 📌 TL;DR（3–5 行）

1. **产品重新定义**：MobileClaw 是**跨 App 连接层**，不是文件整理工具。区分标准 = **"能不能把两个本来不相干的 App 连起来"**；五种连接模式 **收拢 / 搬运 / 编排 / 代理 / 理解**，其中**收拢与编排的爽感最大，且基本落在合法通道（1–4 层）内**。
2. **主入口**：**对话为主干，分享是入口之一**；从别处分享进来的内容**投进对话继续**，**不另起独立向导流程**。
3. **能力硬事实**：234 App 中仅 89 个至少能对外干一件事；覆盖面最广的是"**接收分享**"家族（同一 `ACTION_SEND(_MULTIPLE)` 门）；"**发出去/代理**"类门 ≈ 0（微信 5 项能力全是"接收分享"）——所以**代理必须是进阶包，不进主包承诺**。
4. **产品好坏 = 能否尽量待在通道 1–4 层，只在必要时下到 5–6**；**tier5–6 占比越低越好**（可观测的北向健康度指标）。
5. **纪律红线**：不删任何能力项；不引入未经拍板的一等约束；不承诺"读取其他 App 数据 / 让微信发消息·读聊天记录"进主包；不把"上架"当产品价值；`docs/worklog/` 已跑通实现按"已有"计。

## 1. 产品目标

### 1.1 总目标（新定位补充）

> 让 MobileClaw 成为**手机里唯一一个能"跨 App 连接"的助手**——把散落在不同 App 的信息**收拢**到一起，把一件事**编排**到多个 App 上完成，并且**每一次连接都可见、可拒绝、可回看、可携带**。

### 1.2 三条长期目标（沿用旧 PRD，继续有效）

三阶段目标**正交**——任一未被满足，产品不成立。

| # | 目标 | 说明（新定位下的表述） | 关键指标锚点 |
|---|---|---|---|
| **G1** | **零门槛** | 让不会写宏/开终端的中间层用户，在**不进入任何系统设置**的前提下，一句话完成一次**真实的跨 App 动作** | 首次价值达成率 ≥50%；首值时延 <90s；解析成功率 ≥90% |
| **G2** | **可信可控** | 把 Agent 的每一次动作变成**可见、可拒绝、可回看**的授权事件 | 任务成功率 ≥85%；审批超时率 <5%；**数据损失事件数 = 0（硬约束）** |
| **G3** | **可移植** | 同一套内核与用户的技能/记忆**跨设备携带**，反厂商锁定 | 模型可换使用率 ≥10%；端侧启用率 ≥5%；换机迁移成功率 ≥90% |

- **G1 反"被引导来的一次性"**（North Star 用无提示自发发起度量）；**G2 反"幻觉落地"**（陈述必须由代码从实际执行事实生成）；**G3 反"锁死在单一厂商模型"**。

### 1.3 North Star

> **7 日内无提示主动发起 ≥2 次动作的用户 / 周活用户（自发复用率）。**

跨 App 定位下新增校验指标见 §10.3（跨 App 动作率 / 每会话跨 App 数 / 连接对覆盖率 / 五模式分布 / 通道分层 tier5–6 占比 / 深链专项）。

> **证据纪律（本次新增前提）**：任何"因为政策 X 所以不做 Y"的结论，**必须同时给出"若不考虑 X，Y 是否成立"**。分发（上架）是**待拍板项**，不是一等约束。

## 2. 用户故事

> 入口列改为 **"对话主干 + 分享入口"**：主入口是对话；分享 / 选中文字 / 深链是**把外部内容送进对话的三条门**。跨 App 场景覆盖**收拢 / 搬运 / 编排**；**文件动作场景（原 US1–US4 / J8）保留不得删**。

### 2.1 跨 App 场景故事（新，覆盖收拢 / 搬运 / 编排）

| # | 模式 | 故事：作为〈谁〉，我要〈什么〉，以便〈价值〉 | 主流程 | 成功判定 | 失败/边界 | 通道 |
|---|---|---|---|---|---|---|
| **US-C1** | **收拢** | 作为忙碌的知识工作者，我要**一句话看到"今天所有 App 里谁找我"**，以便不漏事 | 对话输入"今天谁找过我" → 枚举本机可收拢来源 → 汇总 → 逐条可跳转原 App | 汇总条目来自**真实存在的来源**，每条可溯源 | 图片/语音/红包读不到 → 必须如实标注"该来源不可读"，不伪造 | 2 + 4 |
| **US-C2** | **搬运** | 作为爱做笔记的人，我要**把浏览器/聊天里看到的一段文字 → 总结 → 存进笔记**，以便沉淀 | 选中文字（`ACTION_PROCESS_TEXT`）或分享进 → 落到对话继续 → 总结 → 写入笔记 App | 笔记里出现正确内容 | 目标 App 不支持写入 → 回退 Share sheet，不静默失败 | 2 |
| **US-C3** | **编排** | 作为常出差的人，我要**"下周三去上海" → 建日程 + 查车票 + 存地址 + 设提醒**，以便一次搞完 | 对话一句话 → `confirm_plan` 复述 → 逐 App 深链执行 → 结果清单 | 每个子动作有结果、失败可单独重试 | 默认 `maxSteps=12`，跨应用任务约 11–16 步**必然超预算** → 需预算机制（REQ-06） | 2 |
| **US-C4** | **搬运** | 作为收到地址/电话的人，我要**地址 → 存联系人 → 导航**，以便当场出发 | 分享文本 → 解析 → 预览 → 写联系人（系统标准数据）→ 深链导航 | 联系人正确、导航打开正确目的地 | 时间/地点歧义 → 预览高亮待确认；无权限 → 引导授权，不静默丢 | 2 + 系统 API |
| **US-C6** | **代理**（进阶包，不承诺主包） | 作为愿意侧载的极客，我要**替我进某 App 点/发**，以便完成无 API 的封闭操作 | 侧载 + Shizuku → 任务复述 → **发送前收件人核对** → 执行 → **写入后回读核对** | 发错人可拦截；陈述由代码从事实生成 | 微信封号/不可上架/重启需重授权；**明确代价后由用户自选** | 5–6 |

> US-C1–C4 属**阶段 1（合法通道）**；US-C6 属**阶段 2 侧载进阶包**（模式保留、不进主包承诺）。

### 2.2 文件动作场景（保留，不得删 —— 原 US1–US4 / J8）

| # | 故事 | 入口 | 成功判定 | 归属/阶段 |
|---|---|---|---|---|
| **US1（保留）** | 收到一堆课件的学生/职场人：**一句话批量重命名**，不必逐个改 | 分享多选 | 预览 = 实际结果，可回滚 | 中间层·阶段 1 |
| **US2（保留）** | 效率控：**清整杂乱目录、先预览再归档**，敢执行 | SAF 目录(tier2) | 预览 = 执行，可撤销 | 中间层·阶段 1 |
| **US3（保留）** | 临时收文件的人：**在手机端当场归档**，不堆下载区 | 分享单/多文件 | 落到指定目录 + 通知 | 中间层·阶段 1 |
| **US4（保留）** | 健忘的忙碌者：**自然语言建备忘/日程** | 分享文本 | 日历出现正确条目 | 中间层·阶段 1 |
| **US-C5（J8 保留）** | 作为临时收文件的人，我要**一句话批量重命名/归档**，以便不逐个改 | 分享多选 → 落到对话 → 输指令 | 预览 = 实际结果，可回滚；**绝不静默覆盖** | 阶段 1（SAF tier2 需先见价值） |
| **US5（保留）** | 独立开发者/极客：**编排 Termux/脚本、离线直读、BYOK** | 极客层 | 多步跑通、数据不出机、换端续用 | 核心·阶段 2 |

### 2.3 关键边界与异常（必须落进验收标准）

- 批量 200 文件：分批 + 虚拟列表，同类动作"**一次确认**"，进度可见可取消；部分失败给逐项清单，成功保留、失败可重试。
- 重名/冲突：默认加序号或跳过，**绝不静默覆盖**；中文/emoji/空格/超长名保 UTF-8、不拆代理对，超长**报错而非静默截断**。
- **分享进来非文件（纯文本/图片/链接/混合）**：类型嗅探分流，**统一投进对话继续**（文本可不经文件路径）；混合 → 让用户选处理范围。
- 中途取消审批：立即停止；已执行保持、未执行丢弃，可回滚。
- 权限被拒/授权过期（SAF/日历/联系人）：说明"哪步需何权限" + 重授权深链，**不静默失败**。
- 无网/模型不可用：明确报错，配端侧则本地降级，**不伪造结果**。
- **模型返回越授权范围动作**：PathGuard 词法绝对拦截 + 给理由，**直接拒绝、不进审批**。
- **读不到 ≠ 没有**：语义树/Provider 读不到内容时必须如实说明，**不得让模型推测**（对应纪律项）。
- **跨 App 编排超步数预算**：给明确状态，而非"跑到一半停住"（REQ-06）。
- 分享出去目标 App 不支持：回退通用 Share sheet；提示可复制文本。

| 层级 | 人群 | 规模 | 特征 |

### 3.4 跨 App 场景痛点（8 条）

1. 收拢"谁找我"可用，但**图片/语音/红包读不到**（语义树只有占位节点）；
2. `ACTION_PROCESS_TEXT` 真机**已有 12 个 App 注册**（可用的入口已存在）；
3. 一句话多 App 编排可行，但**默认 `maxSteps=12` 必然超预算**（跨应用任务 11–16 步）；
4. 代理 = 发微信**极难**——微信 5 项能力全是"接收分享"，**没有"发出去"的门**；
5. 代理 = 读聊天**只能拿文字**，且**发错人不可撤销**；
6. "**跳进去的多开着、取出来的多锁着**"（能跳的门开着，能取的数据锁着）；
7. 中间层对 **SAF 授权摩擦**容忍度待验；
8. 哪些 App 属"**理解**"模式，需逐个实测。

### 3.5 现有替代方案的不满

| 替代 | 不满 |
|---|---|
| Tasker | 需自建宏，**无 LLM** |
| OpenClaw | 需常连 Gateway |
| ChatGPT / Claude | **只读不落地** |
| 厂商内置（小爱/小V） | 能平替文件动作，但**锁死自家模型**、无 BYOK/审计 |
| Operit / PokeClaw | 模型可换，但**只能侧载**、微信严重封号 |

### 3.6 证据否决项（哪些**不能承诺**）

- 主包承诺"**读取其他 App 的数据**"；
- 主包承诺"**让微信发消息 / 读聊天记录**"；
- 分享结果"**原地改好回原 App**"；
- **无障碍当"主路径"**（→ 归侧载进阶包，**不删除**）；
- "**读不到 = 没有**"。

### 3.7 待验证假设（建议 5–8 名用户）

1. SAF 授权摩擦容忍度；2. "收拢"是否真需求；3. 跨 App 编排的"爽感"强度；4. 深链可靠性的**用户感知**；5. "分享进 → 落到对话"入口是否自然；6. 预览 + **一次逻辑确认**能否缓解确认疲劳；7. 代理模式在侧载用户中的**封号风险意愿**；8. 模型可换 / 数据不出机是否是**真实迁移驱动**。

## 4. 竞品对比

> 采用需求调研报告 §4（竞析）。

### 4.1 五层全景

| 层 | 代表 | 路线 | 短板 |
|---|---|---|---|
| **L1** 系统厂商内置 | 小爱 / 小V | 端侧/系统级 | **锁死自家模型**，无 BYOK/审计 |
| **L2** 开源 local-first | Operit / PokeClaw | 侧载 | 只能侧载，**微信严重封号** |
| **L3** 跨端 Agent | OpenClaw 移动端 / iOS 快捷指令 | 须连服务/Gateway | 依赖常连后端 |
| **L4** 自动化工具 | Tasker / MacroDroid / AutoX | 宏/规则 | **要写宏，无 LLM** |
| **L5** 通用 AI 助手 | ChatGPT / Claude / AI Edge Gallery | 云/端 | **只读不落地** |

### 4.2 功能矩阵（跨 App 连接维度）

| 能力维度 | L1 内置 | L2 开源 | L3 跨端 | L4 自动化 | L5 助手 | **MobileClaw 目标** |
|---|---|---|---|---|---|---|
| 跨 App 一句话执行 | 部分 | ✅ | 部分 | ❌（需写宏） | ❌ | ✅ |
| 模型可换 / BYOK | ❌ | ✅ | 部分 | ❌ | ❌ | ✅ |
| 数据不出机 | ✅ | ✅ | ❌ | ✅ | ❌ | ✅ |
| 合法通道内运行（1–4） | ✅ | 部分（偏 5–6） | ✅ | 部分 | ✅ | ✅ |
| 连接可审计（diff/决策/风险分级） | ❌ | ❌ | ❌ | 部分 | ❌ | ✅（差异化） |
| 连接动作可携带/可移植 | ❌ | ❌ | ❌ | ❌ | ❌ | ✅（差异化） |
| 可上架 / 侧载 | 上架 | 侧载 | 上架 | 上架 | 上架 | **待拍板** |

### 4.3 可借鉴（6 条）

1. **深链协议表 = 跨 App"动词表"**（6639 → 281 协议，188/67% 有依据）喂给模型当工具箱，是"**编排**"最低成本实现；
2. **AI Edge Gallery Mobile Actions**：270M FunctionGemma 端侧 function-calling，微调后 **58% → 85%**（→ 端侧窄域路由可行性依据，🔶）；
3. **MacroDroid「File Shared」触发器**：收来源包名做上下文；
4. **OpenClaw 敏感命令默认关 + 逐项 allowlist + 手机批准**；
5. **Operit 权限分级**；
6. **Shizuku 读树免无障碍**（本仓库已实现）——读取通道可待在**通道 6**而不用**通道 5**。

### 4.4 必须规避（6 条）

1. **把无障碍当代理主路径** —— **Operit 明示"微信会扫描无障碍、严重封号"**；
2. 承诺"读取其他 App 数据"（183 接口仅 **12** 可读）；
3. 承诺"**原地改好回原 App**"；
4. **逐条确认 → 确认疲劳**；
5. **高权即执行 / 幻觉落地**（发送前不核对收件人 = 不可撤销；写入后不回读 = 假装做到）；
6. **全盘 / root / Shizuku 当默认**。

### 4.5 差异化空位（3 个）

1. **合法通道（1–4）内的跨 App 连接**——目前无人占据；
2. **"连接可审计"是一等公民**（可回看的 diff / 决策 / 风险分级）；
3. **连接动作可携带 / 可移植**（Skill 包、换机不归零）。
> **不打**"能连 App 数 / 文件覆盖"军备竞赛。

## 6. 跨 App 连接能力模型（本次核心新增）

把 §5 的能力事实落成"**什么模式走什么通道**"的映射。三个正交维度：**能力三层** × **五种连接模式** × **通道分级 1–6**。

### 6.1 能力三层（机制事实）

| 层 | 机制 | 能干什么 | 可否枚举 |
|---|---|---|---|
| **门** | Activity/Service 的 intent-filter | 让别的 App "**跳进来**" | ✅ 可枚举 |
| **数据** | ContentProvider | 让别的 App "**把数据取出来**" | ✅ 可枚举（但**实测多数锁死**，仅 12/183 可读） |
| **参数** | 深链的 host + path | 跳进去之后**带什么** | ✅ 可从 `dumpsys package` 解析 |

### 6.2 能力三层 × 五种模式 → 通道映射（核心表）

| 连接模式 | 一句话 | 主要落点（三层） | **合法通道（1–4）** | 需下探通道（5–6） | 主包内？ |
|---|---|---|---|---|---|
| **收拢** | 把散在 N 个 App 的东西汇到一处 | **门**（接收分享家族）+ **数据**（系统标准数据） | 通道 2（分享/Intent）+ 通道 1（服务层）+ 通道 4（通知监听，官方权限） | — | ✅ **主推** |
| **搬运** | A 的东西加工后进 B | **门**（`ACTION_SEND` / `ACTION_PROCESS_TEXT`） | 通道 2（分享 / 选中文字菜单）+ 通道 3（剪贴板） | — | ✅ **主推** |
| **编排** | 一句话触发跨多 App 一串动作 | **门 + 参数**（深链 verb 表） | 通道 2（深链/Intent） | — | ✅ **主推** |
| **理解** | 不连 App，连它背后的服务 | 服务层 API | 通道 1（API/网页） | — | ✅ |
| **代理** | 替你进某 App 里操作 | 屏幕语义树（**本仓库已实现**） | —（**无合法门**：微信"发出去"门 = 0） | **通道 5（无障碍）+ 通道 6（Shizuku）** | ❌ **侧载进阶包** |

> **代理模式 = 侧载进阶包**：模式**保留在能力模型里**（不删），**不进主包承诺**；代价明确写：**微信封号 + 不可上架 + 每次重启重授权**。

### 6.3 通道分级表（替换旧"上架/不上架"二分法）

| 级别 | 通道 | 代价 | 能否上架 |
|---|---|---|---|
| **1** | 服务层（API / 网页） | 无，最稳 | ✅ |
| **2** | 官方 Intent / 分享 / 深链 | 无 | ✅ |
| **3** | 剪贴板 | 无，需用户手动粘 | ✅ |
| **4** | 通知监听（官方权限） | 低 | ✅ |
| **5** | 无障碍（模拟点屏幕） | **封号、上不了架** | ❌ |
| **6** | Shizuku | 侧载，**每次重启要重授权** | ❌ |

**产品做得好不好，就看它能不能尽量待在 1–4 层，只在必要时下到 5–6。**

### 6.4 三条铁律（写进任何后续设计）

1. **能跳进去的多开着，能取出来的多锁着** —— 所以"收拢/编排"靠"**门 + 参数**"，**不靠"读别的 App 的数据"**。
2. **产品好不好 = 能不能尽量待在 1–4 层，只在必要时下到 5–6。**（**tier5–6 占比越低越好**，作为一条可观测的北向健康度指标。）
3. **代理模式 = 侧载进阶包**：模式**保留在能力模型里**（不删），代价明确写：**微信封号 + 不可上架 + 每次重启重授权**；**不进主包承诺**。

> **落地校验（R↔通道自检）**：本章每条"模式→通道"映射，都必须在需求池（§8）里有对应 REQ；凡落到通道 5–6 的（代理 + 无障碍 + Shizuku），**一律标注"侧载进阶包 / 待验证"，不得写成"否决/不做"**。

## 7. 关键流程（跨 App · 进来 / 出去的真实边界）

### 7.1 一等边界（改写流程定义）

`ACTION_SEND` 的接收方**只能拿到 URI + 临时读权，无法把处理结果写回来源 App**。回程只能靠"**再次调起系统 chooser / 写剪贴板 / 保存到目录**"。Android 14 起才有 ChooserAction，且 AEP 强制使用系统 chooser、**禁止自建分享菜单**。

> **全流程统一表述**：**进来 = 分享 / 选中文字 / 深链；出去 = 再分享 / 保存到目录 / 复制。严禁承诺"原地改好回到原 App"。**

### 7.2 三条"进来"的门（并列）

| 门 | 通道 | 内容形态 | 触发 |
|---|---|---|---|
| **分享**（`ACTION_SEND(_MULTIPLE)`） | 2 | 文件/图片/文字/多选（只给 URI + 临时读权） | 用户在别处"分享给 MobileClaw" |
| **选中文字**（`ACTION_PROCESS_TEXT`） | 2 | 一段文本（上下文最轻） | 用户在任意 App 选中文字 → 菜单 |
| **深链**（`Intent`） | 2 | 一句话跳到目标 App 指定页 | 用户在对话里下指令 |

> **三条门都把外部内容投进对话继续**（对话为主干）；**不另起没有对话的独立向导流程**。

### 7.3 主流程（跨 App 连接）

```
[任意 App] ──分享(ACTION_SEND，仅 URI + 临时读权) / 选中文字(ACTION_PROCESS_TEXT) / 深链──┐
      │                        ← 无法写回来源 App                                          │
      ▼                                                                                    │
[对话主干] 三条门都把内容投进对话上下文（携来源包名）→ 类型嗅探分流（文件/文本/图片/链接/混合）
      │
      ▼
[一句话意图解析 intent_parse] ──越界指令──▶ [PathGuard 词法拦截 · 给理由 · 不进审批]
      │
      ▼
[预览 / 任务复述（confirm_plan）]  ── 编排类任务在此"一次逻辑确认"
      │  拒绝 / 超时 / 中断 ──▶ 零副作用（或保留已执行 + 可回滚）
      ▼
[执行] 通道 1–4 优先：
   · 收拢 → 系统标准数据（联系人/日历/媒体）/ 服务层 API
   · 搬运 → 分享 / 选中文字菜单 / 剪贴板
   · 编排 → 深链 verb 表（188 有依据先发；93 待实测）
   · 写更改/删除 → 一次审批；读/打开 → 零弹窗
   ·（进阶包）代理 → 侧载 + Shizuku 语义树 + 发送前收件人核对 + 写入后回读核对
      │
      ▼
[结果出口] 再分享(系统 chooser) / 保存到目录 / 复制  ──▶ 完成通知（成功/失败计数）
```

### 7.4 边界与退化路径

| 场景 | 行为 |
|---|---|
| 目标 App 不支持写入 | 回退通用 Share sheet，提示可复制文本 |
| SAF 授权摩擦 | 分步引导 + 监控转化；**退化 = 应用私有区 + "改完再分享/保存"**；**不承诺把结果原地写回来源 App** |
| 深链命中失败（93 条待实测） | 回退并**如实报错**；对 93 条**标"待实测"**，不进对外承诺 |
| 读不到（图片/语音/红包等） | **如实标注"该来源不可读"，不伪造** |
| 跨 App 编排超步数预算 | 给明确状态；优先"取 A 写 B 合成一步"，其次一次读多屏，最后才调 `maxSteps` |

## 9. Non-goals

> 改写要点：旧 PRD 的"**不做无障碍自动化**"改为"**主包不做；进阶包可选，代价已列明**"；其余逐条给出"**若不计约束是否成立**"的判断。

| # | Non-goal | 理由 | 备注（若不计约束，是否成立？） |
|---|---|---|---|
| **N1** | 主包**不承诺**"读取其他 App 的数据" | 实测 183 接口仅 12 可读（6.6%）；真正锁死 135（73.8%） | 技术上限，与政策无关 → **无论是否上架都不成立**为主包承诺 |
| **N2** | 主包**不承诺**"让微信发消息 / 读聊天记录" | 微信 5 项能力全是"接收分享"，**没有"发出去"的门** | 技术 + 封号风险 → **侧载进阶包内保留**（REQ-16） |
| **N3** | **不承诺**"分享结果原地改好回原 App" | 回写通道不可靠（`ACTION_SEND` 只给 URI + 临时读权） | 保守承诺，可后续按实测提升 |
| **N4** | **无障碍自动化不做主路径** | Play 政策 + Android 17 AAPM 封 Accessibility；且 **Operit 明示微信扫描无障碍、严重封号** | 归**侧载进阶包**（REQ-16），**不删除**；"**若不考虑上架/AAPM，无障碍做代理技术上成立**"——但代价（封号）不变 |
| **N5** | **不打**"能连 App 数 / 文件覆盖"军备竞赛 | 与"连接质量"错位；数大不等于有用 | — |
| **N6** | **不把"上架"当产品价值** | 上架是分发选择，不是功能 | 与分发路线拍板解耦 |
| **N7** | **不做**"逐文件/逐步弹窗确认" | 训练用户盲点同意，反降安全 | 与 REQ-10 一致 |
| **N8** | 不承诺 `/Android/data`、`/Android/obb` | SAF 也拿不到，硬约束 | 与分发无关，恒不成立 |
| **N9** | 不自建分享菜单 | AEP 强制系统 chooser | 恒不成立（平台限制） |
| **N10** | iOS 一等支持 | 仅降级兼容上报"沙盒禁止了什么" | 平台限制，与上架无关 |

> **纪律**：凡"因政策 X 不做 Y"的条目（N4 尤甚），已补"**若不计 X，Y 是否成立**"——结论：**代理 / 无障碍 / Shizuku 读屏技术上均成立，属分发/合规选择，不属能力缺口**。

### 10.1 一级指标与门槛（沿用旧 PRD）

| 组 | 指标 | 门槛 |
|---|---|---|
| 激活 | 首值达成率 / 解析成功率 / 首值时延 | ≥50% / ≥90% / <90s |

| 质量信任 | 任务成功率 / 审批超时率 / **数据损失事件** | ≥85% / <5% / **= 0** |

### 10.2 埋点事件（旧 12 个，均含 `initiation_mode(self/prompted)`）

`share_in`、`session_start`、`intent_parse`、`preview_shown`、`approval_result`、`exec_result`、`share_out`、`tier2_prompt`、`tier2_result`、`provider_change`、`ondevice_enable`、`error`。

> **入口埋点必须能区分"分享进来"与"自己打开聊起来"**：`share_in`（带来源包名）vs `session_start(initiation_mode=self)`。审批拒绝/撤销率仅观测，**不当目标**。

### 10.3 新增"跨 App 动作"类指标（本次）

| 指标 | 定义 |
|---|---|
| **跨 App 动作率** | 含 ≥2 个不同 App 的会话 / 总会话 |
| **每会话跨 App 数** | 单会话中涉及的不同 App 数（分布） |
| **App 连接对覆盖率** | 已发生的（A,B）连接对 / 可枚举连接对 |
| **五模式分布** | 收拢 / 搬运 / 编排 / 代理 / 理解 各自占比 |
| **通道分层** | tier1–6 分布 + **tier5–6 占比**（北向健康度，越低越好） |
| **深链专项** | `deeplink_attempt / resolved / param_ok` |

### 10.4 虚荣指标（禁用）

总对话数 / 总 token、累计安装量、总文件处理数、未拆分来源的 DAU、"审批通过率 100%"。

### 10.5 隐私硬约束（数据不出机）

- **本地聚合、遥测默认关闭**、侧载/极客版默认全关；
- **禁止上传**：文件内容 / 文件名 / 路径 / tree URI / 剪贴板 / 对话文本 / prompt / API key / endpoint；
- 文件仅上报 `mime_cat` + 分桶 `files_count`，provider 仅上报类别；
- 仅随机可重置安装级 UUID，分组哈希用**设备本地加盐**；
- 本地 90 天滚动删除 + "导出/删除我的数据"。

| **C 分享进 → 落到对话** | 实测：48 App 接收分享·文字 / 59 图片 / 68 任意文件 / 38 多文件；**微信 5 项能力全部是"接收分享"**；但 `AndroidManifest.xml` 现**无任何 `ACTION_SEND` intent-filter**（入口为 0，需新建） | **M** | **2** | 分享面板只给 URI + 临时读权、**无法把结果原地回传来源 App**；文件场景撞 SAF 授权摩擦；入口从 0 建 | **高**：从任意 App 分享进来 → 对话里继续，是"连接层"最直观的演示 |
| **D 深链执行** | 深链字典 **281 个协议**：**188 个（67%）**用途有 App 自声明组件类名作依据；**93 个是通用分发器，只能靠路径关键词猜，需实测** | **L** | **2** | 93 条需逐个真机实测；Android 11+ `<queries>` 解析限制；目标页可能需登录态 | **中**：一句话跳某 App 某页很直观，但可靠域只到 188 条 |

> 说明：四者的**通道层级都在 2 层**，都不触碰 5/6 层，因此"先做哪个"与"要不要上架"是**两个独立问题**——这一步四选项都不受上架约束。**不排序、不拍板。**
