# MobileClaw 产品方向大纲

> 阶段：Brainstorm → 方向收敛 ｜ 作者：析客（需求分析师） ｜ 日期：2026-10-07
> 输入：瑞思（用户研究）· 竞析（竞品格局）· 数析（市场数据）三方结论 + 现有代码库 `E:\code\mobileclaw`
> 交付性质：**方向大纲，非 PRD**（不含功能字段/交互稿）

---

## 📌 TL;DR

1. 手机端"真执行"缺口巨大（中国 67.8% 想要 vs 全球仅 14% 在用），但**分发与合规才是门槛，成本不是**——Play-safe 必须做成一等约束。
2. 主打**方向一：Share 入口 · 一句话文件动作 Agent**——零设置、天然合规、目前无人占据这个 loop，且复用现有代码最高。
3. 护城河是**方向二：可移植运行时 Harness（模型可换 + 端侧可选 + 可审计 + 技能/记忆可携带）**，不在"能整理文件"本身。
4. 三条红线：全盘管家不作大众卖点、跨应用 UI 自动化已死、设备内 Node/Hermes 不碰。

## 一、方向详解

### 方向一：Share 入口 · 一句话文件动作 Agent（A+D 合并）｜⭐主打

- **一句话定位**：从系统分享面板进入、"一句话批量动作、再分享出去"的合规型手机文件 Agent——不进系统设置、不用无障碍。
- **目标人群**：核心人群（独立开发者 BYOK / 隐私敏感者 / 效率控）；入口层面向中间层大盘（想自动化但不会写宏/开终端的用户）。
- **核心价值与 JTBD**：① 一句话批量重命名下载/课件 ｜ ② 清整杂乱目录**先给预览**再归档 ｜ ⑥ 临时收到文件当场归档 ｜ ⑤ 自然语言直接建备忘/日程 ｜ ⑦ BYOK 掌控成本与隐私。
- **依赖能力边界**：
  - ✅ 分享面板接收/回传、Intent、剪贴板、日历、通知（`system_*`）
  - ✅ 应用私有区文件读写 + 批量预览 + 审批（`fs_*` / PermissionGate）
  - 🔧 路线图 3（SAF 授权目录）、路线图 2（后台长任务）
  - ⛔ 跨应用目录（下载/微信目录）全盘扫描——Play 下不可用，仅作极客侧载甜点
- **是否 Play 可上架**：**需 Play-safe build**（`MOBILECLAW_PLAY_SAFE=1`，仅私有区 + SAF）
- **竞争对位**：占据空白点 ②（可控型 Agent）+ ③（不用无障碍的跨应用动作产品化）+ ④（面向普通人的文件整理）；对位 L5 Mobile Agent（形态重合，但我们锚 Share loop）、L2 Tasker/AutoX（我们不写宏）
- **主要风险**：SAF 授权摩擦与用户认知；"整理文件"单点易被有系统权限的厂商平替；loop 无人占据 = 需教育市场；不能承诺全盘。
- **复用度**：**高**（fs/system/PathGuard/审批全现成）

### 方向二：可移植优先的移动 Agent Harness（B+ C 合并）｜⭐护城河

- **一句话定位**：一套 Cordis kernel 同跑手机/CLI/桌面、模型可换可端侧、记忆与技能可携带的开放运行时——换机不归零。（吸收 C 的"端侧 + 数据不出机 + 可审计"为默认属性）
- **目标人群**：核心人群（Termux 极客、独立开发者 BYOK、隐私敏感者）；**非中间层大盘**。
- **核心价值与 JTBD**：④ 编排手机上已装 Termux/脚本做多步任务 ｜ ③ 无网直读敏感文档 ｜ ⑦ BYOK 免订阅。
- **依赖能力边界**：
  - ✅ 纯 TS 无平台依赖 kernel（Node 可单测，已达成）
  - ✅ 可审计审批链（PermissionGate + 事件/日志）
  - 🔧 路线图 1（shell/python/shizuku）、路线图 5（Skill 插件包）
  - 🔧 新增：端侧模型（Qwen3-4B/Gemma，属新原生模块，未列入路线图）
  - ⛔ 设备内 Node/Hermes 跑任意脚本；⛔ 无障碍自动化
- **是否 Play 可上架**：**需 Play-safe build**（核心执行能力不依赖全盘；Shizuku 类具名事项待审）
- **竞争对位**：占据空白点 ⑤（开放可移植运行时）+ ①（AI 原生 + 真手脚 + 可上架三者兼得）；对位 L3 Termux+Claude Code（我们给 GUI + 批准）、L5 Mobile Agent（开源重合，差异在可移植 + 可审计）、L4 OpenClaw 手机瘦客户端（我们离线可用）
- **主要风险**：极客池天花板仅 **1,000 万–3,000 万**；侧载渠道 2026H2 受 Google 注册新规威胁；Shizuku 重启需重授权；端侧模型为新增工程量。
- **复用度**：**高**（kernel/插件/Cordis 全现成，主要补原生模块 + 端侧）

### 方向三：手机端 MCP 能力平台（E）｜生态位

- **一句话定位**：把手机变成 MCP server/client，让桌面 Agent（Claude Code/Codex/OpenClaw）安全调用手机的文件与系统能力。
- **目标人群**：核心人群（独立开发者 BYOK、效率控）外溢至桌面 Agent 用户；偏极客。
- **核心价值与 JTBD**：④ 编排多步任务 + 跨边扩：把"在手机上执行"交给桌面 Agent。
- **依赖能力边界**：✅ 网络与文件/系统能力（私有区 + SAF）｜🔧 新增 MCP 协议层与传输、路线图 2（常驻需前台服务）｜⛔ 全盘访问。
- **是否 Play 可上架**：**需 Play-safe build**（常驻 server 涉前台服务声明）。
- **竞争对位**：空白点 ①⑤；对位 Android Remote Control MCP（无障碍侧载）、Google AI Edge Gallery。
- **主要风险**：目标人群更小众；安全面扩大（server 暴露）；非手机原生场景，复用中等。
- **复用度**：**中**（需 MCP 层/传输，工具与 kernel 可复用）

### 方向四：手机文件第二大脑 / 本地知识库（F）｜延伸

- **一句话定位**：对 SAF + 私有区文件做本地索引与问答的个人知识库——数据不出机。
- **目标人群**：核心人群（隐私敏感者、独立开发者）+ 中间层大盘延续（"整理我的手机"）。
- **核心价值与 JTBD**：③ 离线直读敏感文档 ｜ ② 清整目录 ｜ ⑦。
- **依赖能力边界**：✅ 私有区读取 + SAF（🔧 路线图 3）｜🔧 路线图 2（后台索引）｜🔧 新增本地 embedding/RAG/向量库｜⛔ 全盘索引。
- **是否 Play 可上架**：**是**（纯本地可 Play-safe）。
- **竞争对位**：空白点 ②④；对位 Google AI Edge Gallery（端侧 + 隐私强但技能弱）、厂商内置智能体。
- **主要风险**：工程量最大（RAG/向量库）；手机算力/电量；厂商可平替。
- **复用度**：**中低**

## 三、已被证据否决的方向（不得作为方向提出）

| 被否方向 | 否决依据 |
|---|---|
| 全盘文件管家作大众卖点 | `MANAGE_EXTERNAL_STORAGE` 不在 Play AI Agent 允许类目 → 只能侧载；且我们在"能整理"上不领先（厂商系统权限更强、Termux 有全盘）。仅保留为极客侧载进阶甜点。 |
| 跨应用 UI 自动化（无障碍驱动） | Play 2026-01-28 无障碍政策禁止"自主计划并执行"的 Agent 型应用（Sova AI 已下架）；Android 17 AAPM 封禁非无障碍工具 → 政策 + 技术双死。 |
| 设备内 Node / Hermes 跑任意脚本 | nodejs-mobile 停更于 Node 18（EOL）、新架构支持未证；Hermes 生产环境不 eval 运行时字符串；Android 10+ W^X 禁止执行数据目录文件。 |
| 侧载 / F-Droid 作长期主渠道 | Google 注册新规 2026-09 强制实名 + 上报签名密钥，F-Droid 称"灭绝事件"→ 侧载只能是补充，不能作稳定长期渠道。 |

## 四、通用收口四件套

### 🎯 核心结论卡片

| 项 | 结论 |
|---|---|
| 主推方向 | 方向一（Share 文件动作），以方向二为差异化护城河 |
| 一级约束 | Play-safe build 必做；全盘仅作侧载甜点 |
| 差异化 = | 模型可换 + 端侧可选 + 可审计审批 + 可移植运行时（**非**"能整理文件"） |
| 唯一死线 | 无障碍自动化、全盘大众卖点、设备内任意脚本 |
| 最大不确定性 | 中间层对 SAF 授权摩擦的容忍度 |

### ⚠️ 待确认 + 假设 + Non-goals

**待确认**
- Shizuku 类应用在 Play 的审核态度（是否需 `specialUse` 声明）
- Chaquopy 17 许可条款能否商用
- 端侧模型在目标机型的实测延迟/电量
- 中间层用户对 SAF 授权摩擦的容忍度

**假设**
- AAPM 开启率 <5%，对大盘影响有限（[假设]）
- API 成本 ≈¥1–2/百万输入 token，重度月 ¥5–30，成本非门槛
- minSdk 30 覆盖全球约 83%，为中国合理下限

**Non-goals**
- 不做无障碍 UI 自动化
- 不做全盘文件管家大众卖点
- 不做设备内任意脚本运行时（Node/Hermes）
- 不把侧载/F-Droid 当长期主渠道
- iOS 仅降级兼容，非一等平台
